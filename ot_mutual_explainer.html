關鍵前提：dad / mom 是各自從頭獨立訓練、彼此權重空間互不相關的兩個 PPO agent。這代表「事後對齊、不做任何梯度微調」的融合方式，天生就會很吃力——這點會在第 5 節的結果中直接反映出來。

2資料結構：雙通道權重矩陣的四個象限

create_dual_channel_policy 把每個隱藏層（例如 policy_net.2，64→64）拆成上下兩半：輸出的上半 32 顆神經元固定用 dad 的權重列、下半 32 顆固定用 mom 的權重列。因為上一層的輸出同樣是「上32=dad、下32=mom」，所以每個權重矩陣 W（形狀 [64,64]）可以看成 2×2 的區塊矩陣：

out_half = dad_w.shape[0] // 2
child_module.weight.data[:out_half, :] = dad_w[:out_half, :]   # 上半：整列全部沿用 dad

action_net（輸出馬達扭矩，64→4）不拆分、整層固定用 dad 權重；value_net 因輸出維度是 1（奇數）也整層跳過，兩者都被排除在 OT 對齊之外。

3mutual_ot_initialize_crosstalk：兩步驟

3.1　初始種子（seed）：用自己的純區塊、經上一層的 T 翻譯過去

for name in layer_names:            # 依序處理每個 Linear 層（僅 policy_net，value_net/action_net 被跳過）
    Wd_pure = dad_m.weight.data[:oh, :ih]   # dad 自己左上角純區塊
    Wm_pure = mom_m.weight.data[oh:, ih:]   # mom 自己右下角純區塊
    if T_prev is None:               # 第一層還沒有上一層的對齊資訊
        W[:oh, ih:] = Wd_pure.clone()
        W[oh:, :ih] = Wm_pure.clone()
    else:                          # 後續層：把上一層算出的 T 沿用過來
        W[:oh, ih:] = Wd_pure.float() @ T_prev
        W[oh:, :ih] = Wm_pure.float() @ T_prev.t()
    T_prev = _compute_layer_transport(Wd_pure, Wm_pure)   # 為下一層準備 T

這一步只是給 X_md / X_dm 一個「不是隨機亂數」的合理起點，還沒開始真正疊代收斂。

3.2　疊代收斂（本次改版：X_dm 當錨點，X_md 對齊後與舊值取平均）

for it in range(n_iters):                       # 最多 100 輪
    child_acts = _collect_pure_activations(child_policy, obs_batch, layer_names)  # 256 筆真實觀測跑一次前向傳播
    for name in layer_names:
        X_md = W[:oh, ih:].clone()          # 待更新
        X_dm = W[oh:, :ih].clone()          # 錨點，本輪不變

        acts_upper = acts[:, :oh]           # dad 神經元的真實 activation（256, 32）
        acts_lower = acts[:, oh:]           # mom 神經元的真實 activation（256, 32）
        T = _compute_layer_transport_from_acts(acts_upper, acts_lower)  # (32,32) OT 傳輸矩陣

        X_md_new = 0.5 * (X_md + T.t() @ X_dm)  # 對齊到 X_dm 座標系後，跟舊值平均，平滑收斂
        W[:oh, ih:] = X_md_new
        # W[oh:, :ih]（X_dm）維持不動

    delta = ||X_md_new - X_md||             # 全部層合計的變化量
    if delta < tol: break              # tol = 1e-3
為什麼選 X_dm 當錨點：因為 action_net 完全沿用 dad 權重，最後一層拿到的 64 維向量應該盡量貼近「dad 自己網路本來會產生的分佈」。讓 X_dm（mom 一側）固定代表 mom 自己真實的行為，只讓 X_md（要餵給 dad 神經元的訊號）去對齊它，比讓兩邊互相拉扯、收斂到一個誰都不像的平均值更有明確語意。

4OT 傳輸矩陣 T 怎麼算

def _compute_layer_transport_from_acts(dad_acts, mom_acts):
    # dad_acts, mom_acts: (256, 32) —— 256 筆觀測、32 顆神經元的真實 activation
    d = dad_acts.t()   # (32, 256) 每顆 dad 神經元視為一個 256 維的"行為向量"
    m = mom_acts.t()   # (32, 256) 每顆 mom 神經元同理
    C[i, j] = ||d[i] - m[j]||²                # 32×32 的成本矩陣：dad神經元i 與 mom神經元j 的行為差多少
    T = ot.emd(uniform, uniform, C)     # 精確最優傳輸（Earth Mover's Distance）
    T = T / T.sum(dim=0)                     # 每欄正規化 → 軟置換矩陣（soft permutation）

直覺：C[i,j] 越小代表「dad 的第 i 顆神經元」跟「mom 的第 j 顆神經元」在同樣一批真實 state 上的反應越像。ot.emd 會找出一個總搬運成本最小的配對方案，近似「幫每顆 dad 神經元找一個 mom 裡最像的替身」。

侷限：這只保證「統計上最像」，不保證某個特定 state 下數值完全一致——因為 dad、mom 是兩個完全獨立訓練出來的網路，內部表徵本來就沒有真正的對應關係可言。這是第 5 節結果崩潰的根本原因，不是程式錯誤。

6診斷結論

Layer 0 完全沒問題：輸入是原始 24 維觀測，dad/mom 兩半神經元的輸出各自跟單獨跑起來時完全一致。
Layer 2 開始失真：dad 原本的權重是為「全部 64 維都來自 dad 自己」的輸入訓練的，現在下半 32 維被換成 mom 的訊號，OT 只能提供「統計上相似」的替代值，無法還原 dad 真正期待的精確數值。
誤差逐層累積：到 action_net（完全沿用 dad、且從未參與任何對齊）時，收到的 64 維向量已經與 dad 原本訓練時看到的分佈差異很大，因此輸出的馬達扭矩失真，child 一開局就摔倒。
根本原因是架構性的，不是實作 bug：dad、mom 無共同祖先、各自獨立訓練 → 兩者權重空間本來就不共享同一個 loss basin → 事後對齊（不論哪種 OT 變體）都難以完全修復，這是模型融合研究裡的已知限制，只有搭配微調／蒸餾才能有效修復殘餘誤差。
