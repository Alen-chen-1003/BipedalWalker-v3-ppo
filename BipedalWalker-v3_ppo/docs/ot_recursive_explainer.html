1. 背景：雙通道架構在做什麼

用兩個獨立訓練好的 PPO 策略（dad 與 mom）拼出一個保留雙親身分的子代網路

create_dual_channel_policy 把每一層隱藏層的神經元切成兩半：上半永遠是 dad 的神經元、下半永遠是 mom 的神經元。權重矩陣 W（形狀 [輸出, 輸入]）自然被切成四個象限：

Wdddad→dad（純通道） X_md = Wd[:oh,ih:]mom→dad（交叉通道，右上）
X_dm = Wm[oh:,:ih]dad→mom（交叉通道，左下） Wmmmom→mom（純通道）
dad 純通道 — 保持不動，dad 身分原封不動保留 mom 純通道 — 保持不動，mom 身分原封不動保留 交叉通道 — 這次的重點：既是「算 T」的依據，也是「被寫入」的目標

2. 問題：交叉通道權重「認不出」它面對的輸入

核心矛盾

X_md（右上角）的角色是「dad 的輸出神經元，要去解讀 mom 血統的輸入」。但 dad 訓練時，他自己的交叉區塊權重 Wd[:oh, ih:] 是拿來解讀 dad 自己上一代遺傳下來的下半神經元，跟這一輪真正的 mom 完全無關。如果不做任何對齊處理就直接使用，等於接上一組「認不出眼前輸入」的權重。

3. Optimal Transport 在這裡做什麼

OT 不是「複製貼上」，是幫兩邊神經元找出「誰的功能最像誰」的翻譯字典

dad 交叉區塊
Wd[:oh,ih:]，右上
⇄
OT 最佳傳輸
最小化配對總成本（weight-based）
⇄
mom 交叉區塊
Wm[oh:,:ih]，左下

T 的依據：交叉通道本身

比對的兩個區塊選「鏡像位置」：dad 自己的 X_md 交叉區塊（右上）vs mom 自己的 X_dm 交叉區塊（左下）——這兩塊在四象限裡互為鏡像，跟純通道對角區塊（左上 vs 右下）算 T 是同一種對稱邏輯，只是從對角換成反對角。

全部層統一 weight-based

不管第幾層，一律直接比較「（翻譯過的）交叉權重向量」的數值差距，不使用真實觀測驅動的反應。優點：不需要 env、不依賴抽樣品質、每次結果都是確定性的、算得快。

4. 為什麼這是「遞迴」

符合遞迴的兩個要件：

基本情況（Layer 1）： T₁ = f(Wd_cross₁, Wm_cross₁)　　　# 沒有依賴
遞迴情況（Layer l ≥ 2）： T_l = f(Wd_cross_l @ T_{l-1}, Wm_cross_l)　　# 依賴 T_{l-1}

不只是 T，寫入交叉通道的值也遞迴依賴這條鏈——第 l 層的 X_md 用的是 T_{l-1}（上一層的結果），不是自己這一層的 T。整個網路的交叉通道要照層數順序、一層一層算完才能算下一層，不能跳著算、不能平行處理。

玩具尺寸 oh = ih = 2；示範 T 如何從 Layer 1 遞迴傳到 Layer 2

Layer 1 寫入（沒有上一層 T，精確複製）

Wd,pureWm,pure
神經元 A/X[0.50, -0.30][0.15, 0.75]
神經元 B/Y[0.20, 0.70][0.55, -0.25]
X_md（Layer1） = Wd,pure    X_dm（Layer1） = Wm,pure

Layer 1 自己的交叉區塊（用來算 T₁，交給 Layer 2）

這是另外一組數字，跟上面的純通道無關——Wd_cross、Wm_cross 是 dad/mom 各自原生網路「右上」「左下」的原始值：

Wd[:oh,ih:]（dad 自己右上）Wm[oh:,:ih]（mom 自己左下）
神經元 A/X[0.10, 0.40][0.12, 0.38]
神經元 B/Y[-0.20, 0.30][-0.18, 0.32]

因為是第一層，T_prev is None，Wd_cross_aligned = Wd_cross（不翻譯），直接算距離矩陣：

Cmom-X [0.12,0.38]mom-Y [-0.18,0.32]
dad-A [0.10,0.40]0.00080.0848
dad-B [-0.20,0.30]0.10880.0008

「照順序配對」(A↔X, B↔Y) 的成本最低（0.0008+0.0008），代表這一層 dad 和 mom 的交叉區塊神經元順序恰好對得上：

T₁ = [[1, 0], [0, 1]]   （單位矩陣）

Step A — 用 T₁ 翻譯 Layer 2 的 dad 純通道（寫入用）

值
Wd,pure（layer2）[[0.80, 0.20], [0.10, 0.60]]
Wm[:oh,ih:]（mom 自己這格原始值）[[0.05, 0.35], [-0.15, 0.25]]

因為 T₁ = I，翻譯後不變：aligned_dad = Wd_pure @ I = Wd_pure

X_md（Layer2） = 0.5 × ([[0.80,0.20],[0.10,0.60]] + [[0.05,0.35],[-0.15,0.25]]) = [[0.425, 0.275], [-0.025, 0.425]]

Step B — 用 T₁ 翻譯 Layer 2 的 dad 交叉區塊（算新 T 用）

值
Wd[:oh,ih:]（layer2 dad 右上）[[0.60, 0.10], [0.30, -0.20]]
Wm[oh:,:ih]（layer2 mom 左下）[[0.25, -0.35], [0.05, 0.50]]

因為 T₁ = I，翻譯後同樣不變：

Wd_cross_aligned（Layer2） = [[0.60, 0.10], [0.30, -0.20]] @ I = [[0.60, 0.10], [0.30, -0.20]]

拿翻譯後的結果去跟 Wm_cross（Layer2） 算距離矩陣、求解 OT，得到 T₂——如果有第三層，Layer 3 就會用 T₂ 重複同樣的兩件事，如此遞迴下去。

這個例子裡 T₁ 剛好是單位矩陣，翻譯前後數字一樣，不容易看出「翻譯」的效果——如果 T₁ 是交換矩陣（像第 2 分頁那種距離結構顛倒的情況），Wd_cross_aligned 的兩個數字就會被對調。

8. 已知限制（實驗誠實記錄）

純初始化階段，子代目前還無法直接可用

在這個專案的實測中，不管公式怎麼調整（含這次簡化成全部 weight-based），只要沒有搭配真正的梯度訓練（蒸餾或線上 RL），子代評估 reward 都落在 -77 ~ -133 這個「機器人幾乎立刻摔倒」的區間，遠低於雙親各自 ~308 分的水準。

目前最可信的解釋：子代初始表現太差時，episode 很快結束，線上 PPO rollout 收集不到有效訓練訊號，形成惡性循環；真正修正殘留誤差可能仍需要密集監督訊號（蒸餾）介入。
