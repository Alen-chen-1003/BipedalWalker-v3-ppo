2資料結構：權重矩陣的四個象限

create_dual_channel_policy 把每個隱藏層（64→64）拆成「輸出上半＝dad、下半＝mom」，因為上一層輸出同樣是上32＝dad、下32＝mom，所以每個權重矩陣 W 可視為 2×2 區塊（oh=ih=32）：

純 dad→dad
（全程不動）
X_md：dad→mom
model1，全程不動
X_dm：mom→dad
model0，每輪被翻譯＋更新
純 mom→mom
（全程不動）
左上：dad 神經元收 dad 自己的輸入，從未被破壞 右下：mom 神經元收 mom 自己的輸入，從未被破壞 X_md：扮演 otfusion 裡的「model1」，永遠是原始 seed 值，從不寫入 X_dm：扮演 otfusion 裡的「model0」，每輪被 T 翻譯、跟 X_md 平均後覆寫
action_net（輸出馬達扭矩，64→4）整層固定用 dad 權重，不參與拆分／對齊；value_net 因輸出維度是 1（奇數）也整層跳過。

3每一輪疊代裡實際發生的事（官方單向對齊設計）

3.1　疊代前：初始翻譯（seed，只做一次）

T_prev = None
for name in layer_names:
    Wd_pure = dad_m.weight.data[:oh, :ih]   # dad 自己的純區塊（左上）
    Wm_pure = mom_m.weight.data[oh:, ih:]   # mom 自己的純區塊（右下）
    if T_prev is None:
        W[:oh, ih:] = Wd_pure.clone()       # X_md 初始值：dad 純區塊
        W[oh:, :ih] = Wm_pure.clone()       # X_dm 初始值：mom 純區塊
    else:
        W[:oh, ih:] = Wd_pure @ T_prev
        W[oh:, :ih] = Wm_pure @ T_prev.t()
    T_prev = _compute_layer_transport(Wd_pure, Wm_pure)

3.2　每一輪的五個步驟（本次版本：X_md 當 model1 全程不動、X_dm 當 model0，內部逐層鏈式傳遞 T）

for it in range(n_iters):                       # 最多 100 輪

    # 步驟 ① 蒐集本輪 child 網路的真實 activation（一次前向傳播，抓齊所有層）
    child_acts = _collect_pure_activations(child_policy, obs_batch, layer_names)

    T_prev = None  # 這一輪逐層鏈式傳遞用
    for name in layer_names:
        X_md = W[:oh, ih:]        # model1：只讀取，全程不寫入
        X_dm = W[oh:, :ih]        # model0：這輪要被翻譯、更新的對象

        # 步驟 ② 先用「上一層」算出的 T，校正這一層的 X_dm
        if T_prev is not None:
            X_dm = T_prev @ X_dm

        # 步驟 ③ 用真實 activation 算「這一層自己」的 OT 傳輸矩陣 T
        acts_upper = acts[:, :oh]   # dad 神經元的真實 activation（256, 32）
        acts_lower = acts[:, oh:]   # mom 神經元的真實 activation（256, 32）
        T = _compute_layer_transport_from_acts(acts_upper, acts_lower)

        # 步驟 ④ 把（校正過的）X_dm 翻譯到 X_md 座標系，再跟完全沒動過的 X_md 平均
        t_dm = T @ X_dm
        X_dm_new = 0.5 * (t_dm + X_md)
        W[oh:, :ih] = X_dm_new      # 寫回交叉通道；X_md 完全不寫入

        T_prev = T                  # 把這一層的 T 留給下一層鏈式使用

    # 步驟 ⑤ 計算 X_dm 離目標 X_md 還有多遠，測試「有沒有逐漸對齊」
    gap = ||這輪所有層的 X_dm_new - X_md||
    if gap < tol:  # tol = 1e-3
        break
這個設計借鏡兩個地方：翻譯／平均公式借鏡 otfusion 官方的 geometric_fc = (T.t()@model0權重 + model1權重) / 2（只翻譯「會動的一方」、跟「完全不動的目標」平均）；逐層鏈式傳遞 T_prev 則借鏡官方 aligned_wt = fc_layer0_weight @ T_var 的做法——上一層的對齊結果，會先修正這一層的資料，再讓這一層算自己的 T，而不是每層各自獨立、互不相關。X_md 固定不動是因為 action_net 完全沿用 dad 權重，我們希望最終隱藏向量盡量貼近 dad 自己網路原本的分佈。

4實測結果：X_md、X_dm 有沒有逐漸對齊？

資料來源說明：以下圖表是加入「逐層鏈式傳遞 T」（3.2 節步驟②、⑤）之前跑出來的結果，當時每層還是各自獨立算 T。加入鏈式傳遞後尚未重新實測，這部分待補上新數據。

用新公式（第 3 節）重新測過，這次追蹤的指標改成 |X_dm − X_md|——直接測「這輪的 X_dm 離固定不動的 X_md 還有多遠」，用來回答「兩者是否逐漸對齊」這個問題，而不是像之前那樣只看「這輪動了多少」。

怎麼解讀這個結果

第 1～6 輪差距快速從 10.42 降到 8.2~8.6，但第 7 輪之後就卡在 8.1～8.76 之間，完全沒有繼續往 0 靠近。
這不代表 OT 對齊失敗。差距不會收斂到 0，其實是預期中的結果：X_md（dad 自己的權重）跟 X_dm（mom 翻譯後再跟 X_md 平均出來的權重）本來就應該保持不同——公式裡有「平均」這個動作，X_dm_new 定義上就不會等於 X_md，除非翻譯後的 t_dm 剛好也等於 X_md。所以「差距趨近 0」從一開始就不是正確的收斂目標。
但真正該關注的是：這個差距本身有沒有穩定下來。答案是沒有——第 7 輪之後這個值仍在 8.1～8.76 之間持續隨機跳動（標準差 0.14），代表 X_dm 每一輪都還在小幅度改變，沒有真正定下來。這跟我們先前多次遇到的問題同源：T 每輪重新用當下的 activation 重算，EMD 精確解在配對成本打平的局面下容易在相近方案間跳動，導致 X_dm 一直有殘餘的抖動。

5與 otfusion 官方設計的對照

項目otfusion 官方本專案 ot_mutual（目前版本）
對齊對象兩個各自獨立訓練的完整模型同一個權重矩陣裡的兩個交叉區塊（X_md、X_dm）
翻譯方向只翻譯 model0，model1 完全不動只翻譯 X_dm（model0角色），X_md（model1角色）完全不動
平均公式(T.t()@model0 + model1) / 2(T@X_dm + X_md) / 2
是否疊代否，逐層單次通過，從第一層到最後一層各算一次 T是，同一組區塊反覆疊代最多 100 輪
成本矩陣依據weight 或 activation，可切換activation-based（256 筆觀測）
層與層之間是否鏈式傳遞 T是，aligned_wt = fc_layer0_weight @ T_var是（新加入）：每輪內部，上一層的 T 先修正這一層的 X_dm，再算這層自己的 T
最大的結構差異在於「要不要疊代」：官方完全不需要疊代收斂，因為它的成本矩陣是拿「兩個訓練好、穩定不變」的模型權重比較，一次算完就結束；我們的 X_md、X_dm 本身不是訓練出來的獨立實體，只是同一個網路裡待填的占位權重，套用「單向翻譯＋平均」的公式後，理論上應該用同官方一樣「算一次就好」，而不必疊代 100 輪——這點可以在下次測試時驗證：只跑 1 輪 vs 跑滿 100 輪，child 表現是否有差異。「層與層是否鏈式傳遞 T」這點原本是本專案跟官方的差異之一，現在已經補上，讓每輪內部逐層處理的方式更貼近官方設計。
