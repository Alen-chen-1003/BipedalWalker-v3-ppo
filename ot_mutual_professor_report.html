2資料結構：權重矩陣的四個象限

create_dual_channel_policy 把每個隱藏層（64→64）拆成「輸出上半＝dad、下半＝mom」，因為上一層輸出同樣是上32＝dad、下32＝mom，所以每個權重矩陣 W 可視為 2×2 區塊（oh=ih=32）：

純 dad→dad
（全程不動）
X_md：dad→mom
本次版本的錨點，全程不動
X_dm：mom→dad
每輪被更新
純 mom→mom
（全程不動）
左上：dad 神經元收 dad 自己的輸入，從未被破壞 右下：mom 神經元收 mom 自己的輸入，從未被破壞 X_md：dad 神經元卻要收 mom 傳來的訊號——本版本固定當錨點 X_dm：mom 神經元卻要收 dad 傳來的訊號——本版本每輪疊代更新這一塊
action_net（輸出馬達扭矩，64→4）整層固定用 dad 權重，不參與拆分／對齊；value_net 因輸出維度是 1（奇數）也整層跳過。

3每一輪疊代裡實際發生的事

3.1　疊代前：初始翻譯（seed，只做一次）

T_prev = None
for name in layer_names:            # 依序處理 policy_net 的每個 Linear 層
    Wd_pure = dad_m.weight.data[:oh, :ih]   # dad 自己的純區塊（左上）
    Wm_pure = mom_m.weight.data[oh:, ih:]   # mom 自己的純區塊（右下）
    if T_prev is None:
        W[:oh, ih:] = Wd_pure.clone()       # 第一層：X_md 直接用 dad 純區塊
        W[oh:, :ih] = Wm_pure.clone()       # 第一層：X_dm 直接用 mom 純區塊
    else:
        W[:oh, ih:] = Wd_pure @ T_prev      # 後續層：用上一層算出的 T 翻譯過來
        W[oh:, :ih] = Wm_pure @ T_prev.t()
    T_prev = _compute_layer_transport(Wd_pure, Wm_pure)   # 為下一層準備 T

3.2　每一輪的四個步驟（本次版本：以 X_md 為錨點）

for it in range(n_iters):                       # 最多 100 輪

    # 步驟 ① 蒐集本輪 child 網路的真實 activation
    child_acts = _collect_pure_activations(child_policy, obs_batch, layer_names)
    #   跑一次前向傳播，256 筆隨機觀測，擷取每層 Linear 的輸出（tanh 之前）

    for name in layer_names:
        X_md = W[:oh, ih:]        # 錨點，本輪讀取但不更新
        X_dm = W[oh:, :ih]        # 待更新

        # 步驟 ② 用真實 activation 算 OT 傳輸矩陣 T
        acts_upper = acts[:, :oh]   # dad 神經元的真實 activation（256, 32）
        acts_lower = acts[:, oh:]   # mom 神經元的真實 activation（256, 32）
        T = _compute_layer_transport_from_acts(acts_upper, acts_lower)
        #   C[i,j] = ||dad神經元i的256維行為 - mom神經元j的256維行為||²
        #   T = ot.emd(uniform, uniform, C)　← 精確最優傳輸

        # 步驟 ③ 對齊後跟舊值取平均，寫回 X_dm
        X_dm_new = 0.5 * (X_dm + T @ X_md)
        W[oh:, :ih] = X_dm_new
        # X_md（錨點）維持不動

    # 步驟 ④ 計算本輪變化量，判斷是否收斂
    delta = ||這輪所有層的 X_dm_new - 上一輪的 X_dm||　# 全部層合計的 L2 norm
    if delta < tol:  # tol = 1e-3
        break          # 提早停止
為什麼選 X_md 當錨點：action_net 完全沿用 dad 權重，最後一層拿到的 64 維向量應盡量貼近 dad 自己網路本來會產生的分佈。讓 X_md（dad 側）固定不動，只讓 X_dm（mom 側）去對齊它，比兩邊互相拉扯、收斂到一個誰都不像的平均值更有明確語意。

前 19 輪有明顯的下降趨勢（10.76 → 4.34），但第 20 輪之後就進入穩定的「震盪區間」，在 4.3～6.9 之間反覆上下，第 20～100 輪的標準差仍有 0.52，跑滿 100 輪都沒有跌破 tol=1e-3，沒有觸發提早停止。

結論：用 activation-based 成本＋精確 EMD＋X_md 錨點，這次仍然沒有收斂，只是從「完全不降」變成「先降一段、後面卡在一個震盪區間」。跟先前用 weight-based 成本測試時觀察到的現象一致：只要 OT 用的是精確解（EMD），最佳解落在傳輸多面體的頂點上，成本矩陣稍有變動就可能整個跳到另一個頂點解，導致 T、進而 ΔX_dm 無法真正收斂到 0，只能在一個範圍內反覆震盪。

6下一步待討論

1. 目前所有版本的 child 評估分數都落在 -100～-116 之間（dad/mom 約 308），零微調的雙通道拼接＋OT 對齊，在沒有共同祖先的前提下難以產生可行走的策略。

2. OT 疊代收斂品質（震盪 vs 平滑收斂）已被隔離驗證：不是造成 child 崩潰的原因。

3. 可能的後續方向：(a) 改用有共同祖先／同一世系分支演化出的模型對測試，驗證「共享 loss basin」假設；(b) 接受零微調融合的天花板，改為融合後加入少量微調步驟。
